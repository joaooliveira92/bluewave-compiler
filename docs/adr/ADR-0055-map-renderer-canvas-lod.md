# ADR-0055: Map renderer — Canvas 2D with pre-simplified LOD tiers

Status: accepted (2026-10-07). Spec: `.scratch/rtw3-parity-ux-overhaul` (M-2, M-5..M-7).

## Context
Owner wants a powerful world map with deep zoom. Current coastline is already
Natural Earth 1:10m (2,779 polygons, 376,002 points, quantised 0.01° ≈ 1.1 km),
drawn as SVG, camera 0.9x–14x.

## Spike result (node micro-benchmark, project + bbox-cull, 1600x900 viewport)
| scale | ms | points projected | points in view |
|---|---|---|---|
| 1x | 13.3 | 340,616 | 334,876 |
| 4x | 5.3 | 182,669 | 57,123 |
| 14x | 3.2 | 85,042 | 7,072 |
| 60x | 2.8 | 79,238 | 206 |

Geometry preparation is cheap; the cost at world view is drawing ~335k segments
into the DOM. At 60x only ~200 points are visible — deep zoom is limited by
data precision, not by renderer.

## Decision
1. Canvas 2D (via `d3-geo`, already a dependency) replaces the SVG coastline
   layer. No MapLibre/deck.gl: no tile server, no new native/WebGL dependency,
   determinism of the app is unaffected.
2. Three LOD tiers generated by Douglas–Peucker at bake time. Measured on the real
   data: tolerance 0.1° -> 20,720 pts (zoom < 3x), 0.02° -> 92,540 pts (3x–8x),
   full 376,002 pts (>= 8x). Generator: `lib/simplify-geometry.ts` (~100 ms total).
   Per-polygon bounding boxes for culling.
3. SVG stays for interactive overlays (areas, markers, labels).
4. Strategic zoom limit rises beyond 14x; the practical ceiling is the 0.01°
   quantisation (~1 km). Tactical maps (50 m/px) are open-sea; shorelines inside
   tactical battles are deferred until a higher-precision shoreline source is
   researched (recorded deferral, not fabricated).

## Consequences
Smaller render cost at every zoom; new bake step and tier module (ticket 02).
