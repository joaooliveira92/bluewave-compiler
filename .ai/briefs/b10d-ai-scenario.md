# B10d Milestone: AI Legality + Scenario Readiness

## Scope

### AI (aligned to DESIGN-50)

Minimum viable AI: **legal-only command generation**. For each AI nation, after the human's `command_collection` phase and before the automated phases, an `AI_PLANNING` phase generates legal commands for every command type that AI nations can issue. The AI does not strategize — it enumerates legal options and picks uniformly at random using a keyed RNG stream.

In scope:

- **AI phase placement**: A new `AI_PLANNING` phase in `PhaseRegistry` (order between `command_collection` and `appropriation`), running only for `type: "ai"` slots. AI nations do not receive commands from the command queue — commands are generated by the AI planner inside this phase.
- **Legal-only command enumeration**: For each AI nation, for each command type that AI can issue at this stage (budget/research-priority), enumerate all legal targets:
  - `budget_project`: every incomplete construction project where the nation has treasury ≥ 0 (budget can be any amount from 1 to min(treasury, remainingWork)).
  - `set_research_priority`: every valid field-priority assignment (1–5 HIGH fields, etc.).
- **Uniform random selection**: Use RNG stream `ai/planning/nation/type` with keyed deterministic selection. No weighted preference, no strategic heuristic.
- **Command lifecycle integration**: Generated commands pass through `CommandLifecycle.process()` identically to human commands — same validate → authorize → reserve → accept → lock → resolve pipeline. Rejected commands produce a diagnostic and the AI does not retry that command in the same turn.
- **AI-only command types**: The `SetResearchPriorityCommand` (B10b) is an AI command type. AI research priorities are set via the same command type as the human — no special AI-only command.
- **Idempotency**: AI commands use deterministic idempotency keys derived from `campaignId`, `turnNumber`, `nationId`, and `commandType` so replay produces identical command sets.
- **Determinism**: Given the same campaign seed, turn number, and state, the AI produces identical command sets and selections. The RNG stream key includes `ai`, `planning`, nation id, and command type.
- **No direct state mutation**: AI must never mutate `CampaignSnapshot` directly. All state changes flow through the command lifecycle and subsequent phase execution.

Explicitly out of scope for B10d (deferred):

- **Strategic AI**: Any weighted preference, heuristic, or goal-driven planning (always build ships, always research certain fields, budget forecasting) — deferred to B11+.
- **DESIGN-50 components**: None of the 23 AI components (StrategicPlanner, BudgetAllocator, ForceStructurePlanner, etc.) are implemented. Only legal enumeration + random selection.
- **National traits or AI difficulty levels**: No difficulty modifiers, no trait-driven behavior.
- **Intelligence insight for AI**: AI sees the full global state (no fog of war); intelligence/knowledge restrictions are deferred.
- **AI battle acceptance policy**: B10d does not add AI decision-making for accepting/declining battle opportunities. Battle resolution remains deterministic auto-resolution for all participants.
- **Diplomatic AI**: No AI diplomacy, war declaration, or peace negotiation decisions.
- **Design AI**: No AI ship design generation.
- **AI learning, scripting, or player-specific adaptation**.
- **Separate AI configuration files or scripting DSLs** — AI behavior is derived entirely from state enumeration and the RNG stream.

### Scenario Readiness

A scenario is "ready" in B10d when it can be compiled, loaded as a campaign, run through a full monthly turn for all participants (human + AI), resolve battles, and pass save/load/replay verification — without any player input beyond an initial set of commands.

In scope:

- **Scenario compilation gate**: A scenario reaching `FULLY_SUPPORTED` readiness (DESIGN-55 §16–17) requires:
  1. **Campaign compilation** — `CampaignCompiler` produces a valid `CampaignSnapshot` from scenario definition and content.
  2. **First turn execution** — `MonthExecutor` runs a full monthly turn for all slots (playable + AI) without crashing.
  3. **Battle resolution** — At least one battle opportunity is generated and auto-resolved for every reachable mission family (surface combat in B10d scope).
  4. **Save/load cycles** — The snapshot can be serialized, persisted, deserialized, and produce a deterministic replay.
  5. **Replay verification** — Two runs from the same seed produce identical final hashes, ledger hashes, and event sequences.
  6. **24-month packaged smoke test** — A fully automated 24-month campaign run with no player input, using legal-only AI for all non-playable slots, ending with ledger-hash verification.
- **Multiple AI participants**: The scenario must support 2+ AI nations executing simultaneous AI planning. Each AI nation generates commands independently in the `AI_PLANNING` phase using its own RNG stream slice.
- **No mandatory human input**: The scenario must complete a full turn without requiring the human to issue any commands. The human slot can issue zero commands and the turn still resolves deterministically. This is the foundation for the 24-month packaged smoke test.
- **`CampaignSlot` typing**: Uses the existing `type: "playable" | "ai"` from `CampaignSlot`. An "ai" slot triggers AI planning; a "playable" slot either receives human commands or zero commands. No new slot types.

Explicitly out of scope for B10d (deferred):

- **Scenario support manifest** (DESIGN-55 §15): The manifest schema is defined in DESIGN-55 but the runtime enforcement (checking manifest hashes, capability closures, era coverage matrix) is deferred. B10d scenarios are verified manually through the acceptance criteria.
- **Capability readiness states** (DESIGN-55 §8): The `CapabilityReadinessState` machine and automated validation are deferred. B10d uses manual acceptance.
- **Packaged smoke test framework**: The build tooling to run packaged smoke tests against the distributable is deferred. B10d acceptance uses `vitest` integration tests that simulate the packaged scenario.
- **Content-only locked isolation** (DESIGN-55 §14): Content gating for unreachable features is deferred.
- **Release support manifest**: No release artifact support claims in B10d.

### Package placement

- **New package `@bluewave/ai`**: Contains `AiPlanner`, `AiCommandGenerator`, and the AI phase integration. This is the first new package since the core packages were established. Separating AI from `@bluewave/phase-engine` keeps the AI system independent and testable.
  - `AiPlanner` — orchestrates AI decision-making per nation per turn. Reads state, enumerates legal commands, selects via RNG, issues commands.
  - `AiCommandGenerator` — generates command envelopes for each command type (budget, research priority). Handles idempotency key derivation and envelope construction.
  - `AiPhaseExecutor` — wraps the AI phase execution for `PhaseRegistry` integration.
- **Extend `@bluewave/phase-engine`**: Add `AI_PLANNING` phase to `PhaseRegistry` (order 1.5, between command_collection and appropriation). The `MonthExecutor` gains a new phase block that invokes `AiPlanner` for each AI slot.
- **Extend `@bluewave/commands`**: No new command types for AI. AI generates the same `BudgetProjectCommand` and `SetResearchPriorityCommand` types.
- **Extend `@bluewave/content-schema`**: No schema changes for B10d AI.

## Out of scope

- Strategic AI, weighted heuristics, goal-driven planning
- All 23 DESIGN-50 AI components
- National traits, AI difficulty levels, AI difficulty modifiers
- Intelligence/fog of war for AI
- AI battle acceptance or tactical decisions
- AI diplomacy, war/peace decisions
- AI ship design
- AI learning, scripting, player adaptation
- Scenario support manifest runtime enforcement
- Capability readiness state machine
- Packaged smoke test framework
- Content-only locked isolation
- Release support manifest claims
- Any B10c (diplomacy/war/peace) capabilities — AI for those systems is deferred to B10c+AI or later
- Desktop UI for AI planning visualization (B9 is CLI-only; B10d stays CLI)

## Acceptance criteria

1. `MonthExecutor` runs a full monthly turn with at least 1 playable slot and 2 AI slots (GBR playable, FRA+GER AI).
2. In each turn, each AI nation generates exactly one `budget_project` command for one incomplete construction project (if any exist and treasury allows), and one `set_research_priority` command (if B10b research is present).
3. AI commands pass through `CommandLifecycle.process()` — rejected commands (e.g., insufficient treasury) produce diagnostics and are not retried.
4. AI commands use deterministic idempotency keys (`campaignId/turnNumber/nationId/commandType`) — replay produces identical command sets.
5. AI command selection uses RNG stream `ai/planning/nation/type` — two runs from the same seed produce identical selections.
6. The 1880 fixture with 3 nations (GBR playable, FRA+GER AI) compiles, runs 24 months with zero human input, and produces identical final hashes on replay.
7. A scenario with 0 human commands still completes a full turn deterministically.
8. All battle opportunities involving AI nations are auto-resolved (AI does not make battle acceptance decisions).
9. Existing compiler, command, phase, persistence, determinism, and B10a/B10b test suites still pass.
10. `vitest run` passes across the workspace (including new `@bluewave/ai` package tests).

## Stop conditions

- The legal-only AI approach conflicts with a DESIGN-50 requirement (e.g., DESIGN-50 requires StrategicPlanner as a minimum — unlikely, but if found, stop and escalate to discuss minimum AI).
- AI command generation cannot reuse the existing `CommandLifecycle` pipeline without architectural changes (e.g., commands must be generated before the `command_collection` phase — then stop and propose a two-pass command architecture).
- The 24-month zero-human-input smoke test cannot pass deterministically due to an invariant that requires human input to progress past a certain state (e.g., treasury exhaustion blocks all AI commands — then stop and add a minimal "always do nothing" fallback for AI with zero legal options).
- `PhaseRegistry` cannot accommodate a phase inserted between `command_collection` and `appropriation` (order 1.5) without a breaking change to the phase execution model (then stop and propose a phase-ordering refactor).
- The existing `CampaignSlot.type` (`"playable" | "ai"`) is insufficient for B10d needs (then stop and propose a slot-type extension).
